# Changelog

All notable changes to Mallard are listed here, newest first, in the format of
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Mallard uses
[semantic versioning](https://semver.org/): before 1.0, a minor release may
change results and inputs, and every such change is listed under **Changed**
with what to do about it. Numbers in parentheses are pull requests or issues.

Pull requests do not edit this file: each one that changes `src/` adds a
fragment to [`changelog/`](changelog/README.md), and a release folds the
fragments in (`python3 tools/dev/changelog.py release X.Y.Z`). Unreleased changes
are this section plus the fragments (`python3 tools/dev/changelog.py notes
Unreleased`); release notes start from `python3 tools/dev/changelog.py notes X.Y.Z`.

## [Unreleased]

## [0.9.1] - 2026-11-01

### Fixed

- Container images and the Spack package pass their release smoke tests; 0.9.0 published no images (#625).
- Container images report their version without a `-dirty` suffix.
- `[[forces]]` on several ranks exchanges the halo before computing the wall gradients: the viscous force read halo cells left from the last stage of the step and differed from the integral of a wall probe's tractions (by 4e-7 in C_D in the measuring tutorial).

## [0.9.0] - 2026-11-01

### Added

- Solution remap between meshes: `[initialize] type = "remap"` starts a run from a restart file of another mesh (any resolution, cell type, partition or rank count), conservatively by supermesh intersection (#353).
- Asynchronous output: files are written on a background thread while stepping continues (`[output] async`, default on; `io_threads`); files are byte-identical to synchronous output (#309).
- Compressed output: `[[write_data]] compression = "zlib"` for VTU and HDF5 (readable by stock ParaView and h5py), error-bounded lossy `relative_error`, and compressed restart files (format version 5) (#309).
- Numerics presets: `[numerics] preset = "robust" | "accurate" | "les" | "reacting"` fills the scheme keys an input leaves unset (#391).
- Mesh readers for CGNS (optional, `-DMallard_ENABLE_CGNS=ON`) (#354), ANSYS Fluent `.msh`/`.cas` (#357) and OpenFOAM polyMesh (#361); `[mesh.transform]` scales, rotates and translates a mesh file as it is read (#350).
- Isothermal (`wall_isothermal`) and heat-flux (`wall_heat_flux`) walls for gas mixtures (#351); `tools/flame_wall.py` for head-on flame quenching against a cold wall (#381).
- Tutorials: supersonic flow over a cone (3D) (#371) and wall-resolved channel LES at Re_τ = 180 (#375).
- User guide by topic with figures from `tools/docs` (#364), theory manual (#372), equations in LaTeX (#370).
- **Boundary options and values** (#564): every boundary type takes its options as keys — `nscbc = { L, sigma, beta, sigma_T, sigma_t }` (non-reflecting), `average = true`, `turbulence`, `wall_model` — and rejects keys and options it does not take with an error naming the type that takes them (``q` doesn't apply to `wall_isothermal`; use `wall_heat_flux``) and, for combinations not supported yet, the plan (#565). The wall temperature of `wall_isothermal`, the heat flux of `wall_heat_flux`, the pressure of `outlet_pressure` (of `t` only with `average`) and the free stream of `farfield` may be expressions of x, y, z, t. Vectors (`u` of inlets, walls and `farfield`, `mass_flux`) are given as components or as a magnitude along `direction` (default: each face's inward normal); a `mass_flux` vector sets the direction and each face's flux. The guide has a section per type and option, and a support matrix that a test compares with the parser.
- **Examples** `heated_wall` (a heat-flux wall whose box gains exactly `q A t`) and `average_outlet` (an area-averaged outlet with subsonic and supersonic faces) (#564).
- `mallard new <template> [dir]`: a ready-to-run case (input with comments, mesh, run and post-processing scripts, README) from 23 examples and tutorials; `--list`, `--quick` for a coarse short version, suggestions for mistyped names (#368, #387).
- Low-storage SSPRK(5,4) and 2N RK4(5) time integrators, and RDPK3Sp35 with error-controlled time steps (`[numerics.error_control]`); about 0.8x the cost of SSPRK3 per unit simulated time (#289, #314).
- Wall-modeled LES: equilibrium ODE and Griffin-Fu-Moin wall models on wall boundaries (`wall_model = {...}`), single gases (#256, #307).
- CUDA compile-only CI jobs (2D and 3D), so host-only changes that break the CUDA build are caught without a GPU (#401).
- `mallard check input.toml`: a pre-flight check without time stepping that reports unused or misspelled input keys (with line numbers and suggestions), boundary zones without a condition, mesh quality with the worst cells (optional VTU), the stable time step and the cell that limits it, memory per rank (also for a target rank count) and the cost of the run (#321, #362).
- Every command has a full help page: `mallard --help` lists the commands by purpose (run, set up, inspect, mesh, maintain), and `mallard <command> --help` (or `-h`, anywhere in the arguments) shows what it does, every option with its default, examples, the exit status and a link to the docs. The pages are collected in the user guide's [Command line](docs/guide/cli.md) page; `mallard mesh --help` and `mallard input --help` list their families (#503).
- `[[mesh.curved]]` projects a boundary zone onto a surface region (2D: a curve), the boundary of any filled region (`filled = false`) or a 2D `circle` or `ellipse`: ellipses and ellipsoids, tori, cones, transformed primitives, booleans and implicit functions, by closest-point iterations on the region's function; circles, spheres and infinite cylinders without transforms keep their closed form, bit for bit. (#407).
- Installation without compiling: container images for each release on `ghcr.io/matthewbonanni/mallard` (CPU for x86-64 and ARM; `:cuda` for NVIDIA A100 to H100), and a Spack package (`spack repo add --path spack/spack_repo/mallard https://github.com/MatthewBonanni/mallard.git`, then `spack install mallard`); `cmake --install` installs every executable, the examples, mechanisms and tools, and 2D and 3D builds install side by side (#328).
- One expression language for every section: local variables (`var`), assignments, `if`/`else`, `switch`, `while`, `for`, `repeat ... until`, `break` and `continue` now also work in `[[sources]]` and regions, compiled for the GPU with results bitwise equal to exprtk on CPUs. Loops stop with an error after 100000 iterations per evaluation instead of hanging a run ([Expressions](docs/guide/input_files.md#expressions)).
- Boundary numbers as expressions of `x`, `y`, `z` and `t`: `u`, `p`, `T` of `inlet_state` (with or without `nscbc`), `p0`, `T0` of `inlet_stagnation`, `mass_flux`, `T` of `inlet_mass_flow`, the wall velocity and mixture compositions, evaluated per face and at every Runge-Kutta stage time, with the `forced_inlet` example (#316).
- A documented compatibility promise for files: every release reads the restart and HDF5 mesh files of the earlier releases of its major version. Fixtures written by 0.6.0, 0.7.0 and 0.8.0 are tested. A file from a newer Mallard is rejected with a message that gives its format version and the versions this build reads. VTU output now carries its format version (field data `MALLARD_FORMAT_VERSION`), and `tools/mallard/vtu.py` and `tools/mallard/h5.py` refuse versions newer than they know (#331).
- libFuzzer harnesses for the input file, expressions and every mesh reader (`-DMallard_ENABLE_FUZZING=ON`, Clang; run them with `test/fuzz/run.sh`), fuzzed for a minute each in CI and ten minutes nightly (#412).
- Initial states from regions: `[[initialize.regions]]` layer `u`, `rho`, `p`, `T` and the composition inside regions over any base state (also a restart or remap), by priority, with cut cells averaged exactly for flat surfaces (second order for curved ones) or whole cells by their centroids (`cells = "center"`) (#324).
- Initial states from data: `[[initialize.data]]` reads CSV tables of one to three coordinates (linear or cubic interpolation) and point clouds (nearest points, or inverse-distance weights), placed by expressions or the distance to a region, as variables of the initial expressions (#324).
- Example `shock_bubble_2d`: a shock on a bubble from a tabulated profile and a tilted slab, set up with regions.
- `mallard check input.toml --catalog keys.json`: the key catalog of an input, every key the setup looked up with its type, physical dimension, default or requiredness and accepted values, as the input accessors record them; `tools/dev/input_catalog.py` merges the examples' and tutorials' catalogs into `docs/input-keys.json` (checked in CI, with the documented defaults of `docs/input.md` checked against it) (#425).
- `[statistics.spectra]`: in-situ spectra and two-point correlations along the homogeneous directions of a generated `cartesian` mesh (per position of the others, e.g. per y of a channel), shell spectra in a periodic box, time-averaged like the means and bitwise identical on any number of ranks; `[statistics.phase]`: per-cell phase-binned means `PHASE_<bin>_<field>`, by a fixed period or by the crossings of a probe variable (#284, #311).
- Restart format 6 carries the averaged spectra; files without them are still written in the older versions (#311).
- `tools/post/insitu_statistics.py` recomputes spectra from restart files, compares them, phase-bins probe series and plots spectra and correlations (#311).
- Each MPI rank picks the GPU nearest its cores by itself (or shares out the GPUs the launcher made visible), and parallel runs print where every rank runs (host, GPU, CPUs, NUMA nodes) with warnings for wasteful placements (#330, #386).
- Job scripts in `tools/jobs/` for Slurm (one node, several nodes), PBS, Kubernetes and `mpirun` that resume from the newest restart, stop cleanly before time limits and resubmit themselves; `mallard -i input.toml --restart FILE` starts from a restart file without editing the input (#330, #386).
- Kubernetes manifests and guide (`docs/guide/k8s`, run control guide): a GPU `Job` that resumes from restart files after preemption, and a multi-node Kubeflow `MPIJob`; the container images include OpenSSH for its launcher and workers (#453).
- `inlet_mass_flow` boundary: subsonic inflow at a given mass flux (`mass_flux`, a number or an expression of `x`, `y`, `z`) or total mass flow (`mdot`, with an optional `profile`) and temperature `T`, whose face flux admits exactly the target mass whatever the inlet density, with the `heated_duct` example against Rayleigh flow (#313).
- Units and descriptions in every output file, by each format's convention: CF `units` and `long_name` attributes on every HDF5 dataset (snapshots, mesh, probes), `<Information>` elements in XDMF, a `MALLARD_FIELD_UNITS` record in VTU/VTP field data, and a `# units:` line under the header of forces, integrals and probe CSV files (per radian in axisymmetric runs, `rad-1`), a `units` column in `[statistics.spectra]` files; `tools/mallard` reads them (`mallard.vtu.units`, `mallard.tables.read_csv`) (#518).
- Probes, region probes, `[statistics]` (with phase averages and spectra) accept the conserved variables `RHOU_X`, `RHOU_Y`, `RHOU_Z` (or `RHOU`), `RHOE` and, for mixtures, `RHOY_<species>` (or `RHOY_*`): a region probe's `integral` gives the momentum, total energy and species masses in the region, for instantaneous control-volume balances with the boundary flux probes (#615).
- Region probes: `[[probes]]` with `region = {...}` write the fraction-weighted integral, mean, min and max (and `favre`, `rms`) of any fields over a region every sampling step, the same bit for bit on any number of ranks (#499).
- Sponge regions: `[[sponges]]` `region = {...}` scales the `strength` by the region's cell fractions, smooth `edge` included (#499).
- Named regions: `[regions.<name>]` defines a region once; every `region` key, and the parts of `union`, `intersection` and `difference`, take its name, and its cell fractions are computed once for all its users (#499).
- Boundary probes: `[[probes]]` with `boundary = "<zone>"` (or a list) or `boundary_type = "wall"` sample every face of the zones, as ordered polylines with arc length in 2D and polygons in 3D: the face states, convective fluxes (`MASS_FLUX`, `MOMENTUM_FLUX`, `ENTHALPY_FLUX`, `SPECIES_FLUX_*`), tractions, wall shear `TAU_W`, heat flux `Q_W`, `CF` and `CP` of a `reference` state, `U_TAU` and `Y_PLUS`, with the same output formats and reductions as other probes. Probe geometry also takes a `pivot` for `scale` and `rotate`, and in 3D `rotate = {axes = [...]}` (#318, #390).
- Surface probes: `type = "cut_plane"` samples the exact intersection of a plane (a line in 2D) with the mesh, one sample per cut cell, with integrals exact for the reconstruction polynomials (clipped to `bounds`). In 3D, the surface of a region (`region = {type = "sphere", ..., filled = false}`, any surface of one primitive, or a flat surface such as a `disk` with `inner_radius`) is resampled on an `n_points = [n_u, n_v]` grid along its parameters, and a parametric `type = "surface"` likewise. Region probes over surfaces and curves without `n_points` sample at their elements' quadrature points. Surfaces, cut planes and 2D curves have the flux variables of boundary probes along their normal, so `reductions = ["integral"]` gives mass, momentum and enthalpy flow through a section (#318, #395, #499).
- The performance set gains `probes_3d`, the `teno5_3d` case with probes every step, measured over time stepping and output (#499).
- `[[probes]]` sample point sets (`points`, `points_file`) and curves (`polyline`, `circle`, `arc`, parametric `curve`), with `translate`, `rotate` and `scale`; `sampling = "point"` reads TENO's reconstruction at each sample (converging at the scheme's order); `time_interval` outputs; `hdf5` and `vtp` (ParaView) formats, versioned; and `reductions` (`integral`, `mean`, `favre`, `min`, `max`, `rms`) along the geometry. Files are bitwise the same on any number of ranks (#318, #358).
- The key catalog (`mallard check --catalog`) lists the accepted values of `parallel.partitioner`, `parallel.halo_exchange`, `physics.gas` and `numerics.convective_flux`.
- Regions of the mesh: `domain` (every cell), every boundary zone (a surface; a curve in 2D) and every cell zone of a mesh file (Gmsh physical groups of cells, Fluent cell zones, CGNS families, OpenFOAM `cellZones`, kept by `mallard mesh convert`) are regions by name, without a `[regions]` entry, in sources, sponges, region probes and booleans; a `[regions]` name that clashes with one, or a cell zone named like a boundary zone or `domain`, is an error (#499).
- Boundaries and interiors: `{type = "boundary", of = ...}` is a region's boundary, one dimension lower, and `{type = "interior", of = ...}` the filled region a closed surface (2D: curve) or closed set of boundary zones encloses; `filled = false` on a filled region or flat surface is its boundary. `circle` and `ellipse` are curves, and in 3D `disk`, `annulus`, `rectangle` and `polygon` flat surfaces (`normal`, `reference`). Wrong dimensions, boundaries of closed regions, interiors of open ones and `edge` on surfaces and curves are errors (#499).
- `mallard check` lists every region a case uses and the mesh's own (domain, boundary zones, cell zones) with dimension, measure, cells and, for surfaces and curves, exact or extracted; a region covering no cell is an error naming its extent and the domain's. `mallard check --view DIR` writes the case view `DIR/case.vtkhdf` (a VTKHDF collection with one block per region and boundary zone, with fractions, normals and measures; `case.vtm` without HDF5) for ParaView (#499).
- Surfaces and curves on the mesh: region probes take surfaces, curves and points (weighted by their area, length or count in each cell). Primitives' surfaces and 3D flat surfaces and curves are exact (sampled on their parameters, exact measures where unclipped); planes, boundary zones and faces of mesh regions come exactly from the mesh; boundaries of booleans and `implicit` regions are extracted from the cells at a settable `resolution` (#499).
- Clipping across dimensions: `intersection` and `difference` of a surface or curve with filled regions keep the part inside (outside) them, e.g. the part of a wall zone in a box; clipped primitives' surfaces are integrated at high order up to the exact clipping boundary (#499).
- Orientation: closed surfaces face out, boundary zones out of the domain, flat surfaces along `normal`, 2D curves to the right of travel, 3D curves counterclockwise about their normal; `flip = true` reverses a surface or curve (#499).
- Regions: the shared syntax for parts of space (spheres, cylinders, cones, boxes, tori, half-spaces, polygons, implicit `f(x, y, z) < 0`, their unions, intersections and differences, with `scale`, `rotate`, `translate` and an optional smooth `edge`), with exact cell volume fractions, in [docs/input.md](docs/input.md#regions); the keys that take a region follow in later releases (#317, #359).
- Snapshots of regions: `[[write_data]]` `region = ...` (or `regions = [...]`, a series per region) writes a filled region as the subset of cells it covers, with only their nodes and `REGION_FRACTION`; a boundary zone, the surfaces and curves of `[regions]` (one sample at each element of the region on the mesh) and probe types given as regions (`type = "cut_plane"`, `"line"`, `"points"`, ...) as the point values a `sampling = "point"` probe writes (cell fields from each sample's cell), in VTKHDF or VTK files, the same on any number of ranks; every region is written again at the end of the run. `[[probes]]` `region` also takes probe types as regions (#542).
- Rotational periodicity: `[[periodic]]` pairs zones by a rotation (`angle`, `center`, and in 3D `axis`) as well as by a translation, with vectors and gradients turned across the pair in every scheme (MUSCL, TENO, viscous fluxes, LES, statistics), and a generated `annulus` mesh type (`r_inner`, `r_outer`, `angle`, periodic in `theta` and in 3D `z`), with the `rotational_sector` example (#315).
- Run control: `SIGUSR1` writes a restart and continues; `SIGTERM`, `SIGINT` and `SIGUSR2` write a restart after the current step and exit with status 3; `mallard ctl <run-dir> status | checkpoint | stop | set <key>=<value>` talks to a running job through a private socket; optional `STOP` and `CHECKPOINT` files (`[run] control_socket`, `control_file_interval`) (#322, #355).
- Divergence detection: every step's time-step reduction flags non-finite states, and the run stops naming the first bad cells and writing the last valid state (`[run] keep_last_good`) (#355).
- Run health diagnostics (`[output] health`, on by default) in every progress record of the run log and a Health section at the end of the human log: smallest density, pressure, temperature and mass fraction with their location and step, TENO troubled, MUSCL limited and hybrid upwind fractions per rank, chemistry sub-steps, rejections and rank imbalance, and output time per rank (#435).
- An independent conservation ledger: domain totals of mass, momentum, energy and element masses against boundary transfers re-evaluated from the boundary faces, re-evaluated sources and the recorded numerical repairs; closes at round-off for conservative setups and flags an unexplained change (#435).
- Audit of the numerical repairs (mass-fraction clipping in the chemistry, the double-flux energy reset): activations, distinct cells and the change they made (#435).
- Provenance: versions of every dependency (MPI library, HDF5, CGNS, zlib, NCCL, CUDA/HIP runtime and driver) and the host count; the run log's start record holds each rank's host, GPU and CPU set, and the setup phase times per rank (#435).
- A JSON-lines run log (`[output] run_log`, default `mallard.jsonl`): a start record with the provenance, a progress record at every progress row (step, time, CFL, throughput, ETA, monitors, memory) and an end record with the wall-time breakdown (#326, #376).
- Provenance in every output file (VTU, PVTU, HDF5, restart, CSV monitors and probes): version, git state, build configuration, resolved numerics preset, input text and hash, mesh hash, ranks and devices; `provenance(path)` of `tools/mallard/vtu.py` reads it (#326, #376).
- `[[sources]]`: any number of mass, momentum, energy and species sources, each a number, quantity or expression of position, time, the local solution (`rho`, `u_x`, `p`, `T`, `Y_<species>`, ...) and domain averages (`mean_ke`, ...), restricted to a [region](docs/input.md#regions) and optionally given as an exact integrated total (`total = true`); evaluated on the device every stage without leaving CUDA graphs. `[[write_data]]` writes them as `SOURCE_*` (#317, #384).
- Examples `source_regions` and `forced_isotropic_turbulence` (linear forcing at a target kinetic energy) (#384).
- `inlet_stagnation` boundary: subsonic inflow at stagnation pressure `p0` and temperature `T0` (with an optional flow `direction`), for perfect gases and thermally perfect mixtures, with the `nozzle` example against the quasi-one-dimensional solution (#312).
- Units in input files: any dimensional key takes a quantity with a unit (`p = "1 atm"`, `T = "25 degC"`, `Lx = "5 mm"`, `u = ["10 m/s", 0]`), converted to SI; a unit of the wrong dimension is an error naming the key, its line and the expected dimension. Plain numbers stay SI (#339, #389).
- `mallard input upgrade old.toml > new.toml` brings an input from an older release up to date. It rewrites renamed, moved and removed keys and options and keeps comments and layout; `--check` exits 1 when a file is out of date. Renamed keys are deprecated first: they are still read, with a warning naming the new key, for at least one minor release before they are removed. `mallard check` lists deprecated keys as warnings and removed ones as errors. The policy and the changed keys are in the user guide under "Inputs from older releases" (#332).
- A verification manual (`docs/verification/`): the observed orders of accuracy of every reconstruction on every cell type, the Euler and Navier-Stokes operators, the time integrators, boundary conditions, curved boundaries, remapping and mixtures, generated from the convergence tests by `tools/docs/verification.py` (#342)
- `[[write_data]] format = "vtkhdf"`: VTK's HDF5 format, read by ParaView 5.12 and later. Volume output is an UnstructuredGrid (curved cells as quadratic Lagrange cells), boundary zones a PolyData; all ranks write one file per snapshot in parallel, or with `series = true` one file holding every snapshot, which a restarted run continues. `compression` and `relative_error` apply.
- `[[probes]] format = "vtkhdf"`: one VTKHDF PolyData file of the samples with their values at every output, continued by restarted runs.
- `tools/mallard/vtkhdf.py` reads VTKHDF output (snapshots, series files, probes); `mallard.vtu.read_vtu_cells` and the plot and animation scripts read VTKHDF or VTU, whichever the build wrote (`mallard.vtu.snapshot`, `read_index`).

### Changed

- **The default TFLES efficiency is `"dynamic"`** (#310): `[les.combustion] efficiency` now defaults to Charlette et al.'s saturated power law with a dynamic exponent, which changes TFLES results. `efficiency = "charlette"` restores the 0.8.0 model; `beta`, `subgrid_velocity` and `C_u` are input errors with `"dynamic"`.
- **The stable time step includes the exterior states of boundary faces** (#374): a fast inflow into slower gas now sets `dt` from the first step, so runs whose boundary states are faster than the adjacent cells take smaller steps.
- **The hybrid convective flux with SIMPLER coupling is rejected** (#300): the combination is linearly unstable and was accepted silently; use Strang coupling or `convective_flux = "riemann"`.
- Distributed runs skip the viscous gradients of halo cells beyond the first layer unless LES models are on (#365); bitwise unchanged.
- **Unknown or unused input keys are now errors** in every run, with the line number and the most likely intended key; boundary zones without a condition are named (#362).
- `[parallel]` is read in every run (#362).
- **Usage errors exit with status 2** and print one line pointing at the command's `--help`: an unknown option (previously ignored by `mallard -i`, `check` and `reactor`), an unknown command, a missing argument. `mallard check`, `reactor` and `mesh convert` exited with 1 on these. Options take their value as `--opt VALUE` or `--opt=VALUE`; `--version` is accepted only as the first argument (#503).
- `mallard test --help` shows Mallard's own page only, which lists the common GoogleTest options (`--gtest_filter`, `--gtest_list_tests`, `--gtest_repeat`, `--gtest_fail_fast`, `--gtest_brief`, `--gtest_output`) with an example each, instead of appending GoogleTest's full page; other `--gtest_*` options still pass through.
- The solvers are `mallard2d` and `mallard3d` (test suites `mallard-test2d`, `mallard-test3d`), installed side by side, and `mallard` runs the one a case needs: by the dimension of its mesh file (Gmsh, Fluent, CGNS, OpenFOAM, HDF5) or, for a generated mesh, 3D when `[mesh]` sets `Nz` or `Lz`; `mallard --dim 2|3` states it. `mallard -i`, `check`, `new <template>` and `mesh convert` pick the dimension; `ctl`, `reactor`, `input upgrade` and `--version` run either solver; `mallard test` runs every installed test suite (`--dim` for one). A case whose solver is not installed is an error naming it and `-DMallard_DIM`. `Mallard_EXECUTABLE_SUFFIX` is removed (#483).
- **`dirichlet` states of `t` are evaluated on the device** at each Runge-Kutta stage time, like every other boundary expression, instead of on the host with a copy to the device per stage; CUDA builds now run such cases as one CUDA graph per step (`[run] cuda_graphs`). States that do not depend on `t` are evaluated once at setup.
- The output guide is three pages: Output (what a run writes, snapshots, terminal output, the run record `mallard.jsonl`, units, provenance and formats), Probes and monitors (`[[probes]]`, `[[forces]]`, `[integrals]`) and Statistics. The docs, error messages and help text call the terminal output and `mallard.jsonl` (the "run record") by distinct names instead of "the log" and "the run log".
- Expressions in `[initialize]`, boundaries, sponges and probe curves are checked by the same compiler as `[[sources]]` and regions, with the same error messages (also from `mallard check`): variable names are case sensitive there too (`X` is no longer `x`), and strings and vectors are rejected.
- Analytical initial states are integrated on the device (the GPU in GPU builds) with the compiled expressions instead of on host threads; cells where the state is uniform take it exactly, others change within rounding (#449).
- **Analytical initial states on quadrilaterals change by their quadrature error (up to 1e-8 relative for states that vary strongly across coarse cells):** cells are averaged over the fan of triangles from their vertex average rather than from their first node, so that they do not depend on the node order of the mesh file (#436).
- **TENO results change in troubled cells:** the smoothness indicators weight each derivative by its multinomial coefficient, and in 3D the two shear waves of a face select their stencils together, so that stencil selection depends neither on the orientation of the axes nor, in 3D, on the cell numbering. TENO cache files of earlier versions are recomputed. There is no switch back (#436).
- One lowercase `mallard` executable with subcommands replaces the separate executables (#414). Everything typed is lowercase; the project, its prose and the CMake `Mallard_*` options keep the name Mallard. Old → new:
  - `Mallard -i input.toml` → `mallard -i input.toml`
  - `Mallard --check input.toml [--catalog keys.json]` → `mallard check input.toml [--catalog keys.json]`
  - `Mallard new`, `Mallard ctl`, `Mallard --version` → `mallard new`, `mallard ctl`, `mallard --version`
  - `MallardReactor -i reactor.toml` → `mallard reactor -i reactor.toml`
  - `mallard-mesh-convert INPUT OUTPUT.h5` → `mallard mesh convert INPUT OUTPUT.h5`
  - `MallardTest` → `mallard-test2d` or `mallard-test3d`, also run as `mallard test [GoogleTest options]`
  - `-DMallard_EXECUTABLE_SUFFIX=3D` (`Mallard3D`, `mallard-mesh-convert3D`) → none: `mallard2d` and `mallard3d` behind one `mallard`
  - CMake targets `Mallard`, `MallardReactor`, `mallard-mesh-convert`, `MallardTest` → `mallard`, `mallard-test`
- `cmake --install` also installs the test suite and its data, so `mallard test` checks an installed build; `-DMallard_INSTALL_TESTS=OFF` leaves them out (#414).
- `[statistics.spectra]` CSV files end each row with a `units` column (the units of its `value`); scripts that read columns from the end of the row should read them by header name, as `tools/post/insitu_statistics.py` now does (#518).

### Deprecated

- **Boundary types renamed** to explicit subtypes, kind first (#564): `upt` is `inlet_state`, `p_out` is `outlet_pressure`, `p_out_average` is `outlet_pressure` with `average = true`, `extrapolation` is `outlet_extrapolation`, and `nscbc_inlet` / `nscbc_outlet` are `inlet_state` / `outlet_pressure` with an `nscbc` table holding their `L`, `sigma`, `beta`, `sigma_T` and `sigma_t`. ### Fixed

- With `double_flux` and `navier_stokes`, the diffusive energy flux reached only one side of each face (steady conduction between walls ended 500 K off) (#351). Changes results of double-flux viscous runs only.
- Distributed runs with `double_flux` and chemistry differed from serial ones by about 1e-7: the halo is refreshed before freezing the thermodynamics (#378).
- The 3D TENO setup no longer fails with "does not fit in memory" on faceted curved boundaries that touch more than 32 mirror planes, such as the far field of `sphere_mach3` (#392).
- A fast inflow into gas at rest no longer blows up the first step (#374).
- `cmake --install --prefix` is honoured (install destinations were absolute), and GoogleTest is no longer installed (#387).
- Mallard compiles with Kokkos' HIP and SYCL backends: the `_r` literal is `consteval` (no `long double` reaches a SYCL device), and the TENO kernels that only GPU builds compile convert their team indices explicitly and capture what their compile-time lambdas use (#402).
- Intel's oneAPI compiler gets Mallard's warnings, the TENO setup's `-ffp-contract=off` and the precise floating-point model, so NaN checks work (#402).
- Single-precision builds compile with Clang again: the wall-model input no longer promotes `float` to `double` implicitly, and CI's Clang build is now single precision so this stays covered (#491).
- `mallard test --help` no longer hangs where MPI cannot start without its launcher (as in the test suite under HPC-X's `mpirun`): it no longer runs a test suite for GoogleTest's page, and `mallard-test2d`/`mallard-test3d --help` start neither MPI nor the device.
- `[mesh] curved_geometry = false` leaves `[[mesh.curved]]` out instead of stopping the run on its keys as unused, as documented (#407).
- Single-precision builds read the center, radius and axis of closed-form `[[mesh.curved]]` circles, spheres and cylinders in double, as the curved geometry is computed, instead of rounding them to single precision first (projections were off by about 1e-8).
- CGNS built from source (`-DUSE_SYSTEM_CGNS=OFF`) compiles against a parallel HDF5 (#328).
- `[source] mass_flow` on CUDA builds: the force's domain sums and the step's `dt` are now taken on the device, so runs whose steps are captured as a CUDA graph no longer replay a force frozen at capture, and a restarted run reproduces the uninterrupted one bitwise. The sums are exact (fixed point), so the forced flow is also bitwise the same on any number of ranks.
- A run with an HDF5 `[[probes]]` file and HDF5 `[[write_data]]` output (written in the background by default) could crash: the probe and the background writer called the HDF5 library at the same time. Every HDF5 call now takes one shared lock.
- On several ranks, a probe file that rank 0 cannot create or continue (for example one from a newer Mallard on a restart) now stops every rank with the error, instead of leaving the others waiting. `ProbesTest` runs on 1 to 4 ranks in CI.
- Extrapolation boundaries are second order on tetrahedra and pyramids: gradient stencils continue across the boundary through the translated image cells, as across a periodic seam, instead of a mirrored ghost of the cell itself, and pyramids find their image faces one cell deep rather than at their apex. A channel with extrapolation sides converged at first order and carried a spurious cross flow (#420).
- MPI runs with a modeled wall and without `[les]` now compute the viscous gradients of the halo cells holding exchange and edge points, which the wall model read stale, so they match serial runs again (#422).
- A malformed input with an unclosed nested array before a key (as in `s=["",["",""[` then a line `[=`) no longer hangs the input reader; it reports the TOML syntax error.
- Malformed input with deeply nested or unclosed arrays and inline tables, a comment inside one (`s=["",[""[#`), or a key on the line of a nested one (`s=[` then a line `"",[""[=`) no longer crashes or hangs the input reader; it reports the TOML syntax error. Tables, arrays and inline tables nested more than 64 deep are an input error naming the key and line, instead of a stack overflow.
- Malformed mesh files are rejected with an error instead of crashing, hanging or exhausting memory: Gmsh files that end early or announce counts past their end, Fluent ids from 0, OpenFOAM files with NUL bytes, oversized lists or faces of missing cells, Mallard HDF5 meshes with bad offsets or node ids, and CGNS sections with bad element ranges or offsets (#412).
- Sources that read domain averages (`mean_rho`, `mean_ke`, ...) no longer depend on the number of ranks or threads: the averages are exact sums, as the dynamic LES and flame-thickening constants already were.
- On several ranks, an input error found in one part of the mesh (a negative mass flux, an inlet `direction` pointing out of the domain, a boundary face assigned twice, a synthetic-turbulence inlet that is not planar or a Reynolds stress that is not positive semidefinite) is reported by every rank, instead of ending the run in an MPI error or a hang.
- The error for a `[[boundaries]]` or `[[forces]]` zone missing from the mesh lists every zone of the mesh on any number of ranks, not the zones of one rank's part (with the internal `__partition__`).
- A boundary value given as an expression that leaves its range (a temperature or pressure that is not positive, a negative mass flux, a zero composition), at setup or during the run, stops every rank with its error, not just the ranks holding the offending faces.
- Probe VTP files hold their field data (`MALLARD_FORMAT_VERSION`, the units record) at the data-set level, where VTK and ParaView read it, instead of inside the piece (#518).
- Bound-preserving TENO (`bound_preserving = true`) keeps density and pressure positive in every cell at `cfl` up to 0.5 in planar single-gas runs: the convective fluxes are blended toward first order on the faces where the update would leave a cell without positive density or pressure. Its face values alone did not guarantee this, and the Mach 8 `mallard` example on its cubic mesh diverged in the near vacuum behind the tail. Faces that need no limiting are unchanged (#603).
- The `difference` region examples of the docs are valid TOML (an inline table cannot span lines); a CI check parses every TOML snippet of the docs (#499).
- Restart files are written as `<name>.restart.partial`, flushed to storage, and renamed once every rank has written its part, so a file named `.restart` is always complete: a run killed while writing one, or a script picking the newest restart while one was being written in the background, no longer finds a truncated file.
- A run resumed from a restart file whose snapshot index (`.vtkhdf.series`, `.pvd`, `.xmf`) was missing, such as one copied to another machine with only its restart file, numbered its snapshots from 0 again and overwrote the earlier ones. Restart files now count each `time_interval` writer's snapshots, so numbering continues after the restart time regardless.
- Characteristic (NSCBC) boundaries of gas mixtures read the current stage's reconstructed `gamma`, not the previous stage's (zero at the first step) (#355).
- The `start` record of a run resumed from a restart file did not say which restart file it started from, so a run record (`mallard.jsonl`) continued several times could not be told apart from a rewind. It now holds `restart` (`file`, `step`, `t`), and `rewound_from` when the run resumes from an earlier restart file than the last step recorded.
- Spack package: `+nccl` passes `cuda_arch` on to NCCL, so `mallard+cuda+nccl cuda_arch=<N>` concretizes.
- A value of the wrong type (`Nx = 16.0`, `Nx = "16"`, `keep_last_good = "false"`) or a negative count is an error instead of silently taking the default or wrapping around; an integer is accepted where a number is expected.
- `run.cfl` and `run.dt` must be positive, and the forces and integrals files must open, instead of failing later.
- 2D TENO no longer settles into an odd-even wall-pressure mode on straight-sided curved walls with thin wall cells (NACA 0012 tutorial mesh, orders 3 and 4; orders 5 and 6 improve): mirror images are taken only across the boundary faces beneath their cells and on the target cell's side, and stencil candidates are ranked in the metric of the local mesh spacing as in 3D. 2D stencils on anisotropic or faceted-wall meshes change, and TENO cache files are recomputed (format version 11) (#382).
- `extrapolation` and characteristic boundary faces without an image face (most faces of unstructured triangles and tetrahedra) take the image cell's TENO-E polynomial at their translated quadrature points instead of its average: against TENO's high-order interior state the average grew round-off in a uniform subsonic inflow into vacuum states and NaNs.
- `mallard input upgrade` on a case whose dimension it cannot tell names the reason, e.g. a mesh file not found relative to the working directory (with that directory), and what to do: run from the case's directory or pass `--dim 2|3` (#499).

## [0.8.0] - 2026-10-15

Curved high-order boundaries, a GPU-resident 3D TENO setup, multi-jagged
partitions, 2× faster reacting mixtures, SIMPLER splitting, Soret diffusion and
optically thin radiation.

### Added

- Curved high-order boundaries (#263): Gmsh 2.2/4.1 boundary elements of order 2 and 3 (kept by `mallard-mesh-convert`) or `[[mesh.curved]]` projection onto a circle, sphere or cylinder; TENO-E orders 3–6 reach their design accuracy at curved walls (`curved_mirrors`, `curved_wall_degree`). `tools/make_annulus_mesh.py`; `--order` for the cylinder and sphere mesh tools.
- SIMPLER balanced splitting: `[chemistry] coupling = "simpler"` (#235).
- Thermal (Soret) diffusion: `physics.soret = true` (#243).
- Optically thin radiation: `[radiation]`, output `QRAD` (#226).
- CUDA graph per step: `[run] cuda_graphs`, default on in CUDA builds (#217).
- NCCL halo exchange: `Mallard_ENABLE_NCCL`, `[parallel] halo_exchange = "nccl" | "mpi"` (#217).
- Chemistry load balancing across MPI ranks: `[chemistry] load_balance = true` (#255, #262).
- Opt-in `single_precision_tables` for 3D TENO (#265) and `chemistry.C_reg` (#264).
- Examples `flame_vortex_quenching`, `premixed_flame/ch4` and `volvo_bluff_body`; performance cases `flame_3d` and `air_3d`; mechanisms `ch4_bfer.yaml` and `c3h8_2step.yaml` (#226, #241, #252).
- Builds with CUDA 13 (#259, #260).

### Changed

- **RHLL blends toward HLL across faces that carry a shock** (#248): RHLL results change wherever a face carries a pressure jump; faces with equal pressures are bitwise unchanged. Other Riemann solvers are unchanged.
- **Multi-jagged partitions are the default** (#261): results are bitwise identical on any rank count, but per-rank output pieces and TENO caches differ from 0.7.0's. `[parallel] partitioner = "hilbert"` restores the 0.7.0 partitions.
- **Gmsh high-order boundary elements curve their faces** (#263): 0.7.0 read them by their corners. `[mesh] curved_geometry = false` restores straight faces; linear meshes are bitwise unchanged.
- 3D TENO tables on macOS arm64 change at round-off (no FMA contraction in the setup) (#247).
- TENO cache format `MALLARD-TENO-10`; older caches are rebuilt (#247, #265).
- The 3D TENO setup runs on the GPU, 6–9.5× faster, bitwise identical (#247); 3D TENO device memory is about 15% lower (#265); MUSCL reconstruction is fused and overlapped with the halo exchange (#239); halo exchanges carry only the cells the stencils read (#258); reacting mixtures are 2× faster per step (#257, #264); large mechanisms solve faster on GPUs (#246).
- `-Wconversion -Wsign-conversion` are on, as errors under `Mallard_WARNINGS_AS_ERRORS` (#267, #269–#276).

### Fixed

- `[integrals] budget = true` with `double_flux = true` threw "Double flux needs the cells' thermodynamics frozen" (#252).
- The 3D TENO host retry wrote compacted cells out of bounds (#263).
- Latent truncations of `Solver::get_step()`, mesh local indices and LU substitution indices (#267).
- The radiation test failed to compile with nvcc under `-Werror` (#268).

- 3D single-precision builds pass every test and run in CI (#237).
- Examples `autoignition_2d` (#174), `detonation_3d` and `shock_bubble_3d` (#183), `cbc_les` (#213), `channel_les` (#214, #230), `flame_turbulence` (#222), `channel_inflow_retau180` and `turbulent_inflow_duct` (#221); `mechanisms/he_air.yaml`.

### Changed

- **Licensed under Apache-2.0** (#231), with a `NOTICE` file; 0.1.0–0.6.0 remain AGPL-3.0-only.
- **Example CFLs raised toward the measured stability limits** (#210): most examples run at `cfl = 1.0`; their results are not bitwise equal to 0.6.0.
- **`channel_retau180` uses the hybrid flux** (#216).
- **3D TENO stencils are bounded by a Lebesgue constant of 4** (#232): changes 3D TENO results on tetrahedra, pyramids, mixed meshes and some prisms and hexahedra next to walls; TENO cache format `MALLARD-TENO-8`.

- MallardReactor's ignition criterion is the peak of dT/dt (#220).
- `eps_numerical` is taken from the scheme's discrete pressure work, new column `pressure_work` (#222).
- 3D TENO smooth pass 2.2× faster on GPUs (#212); TENO setup host memory 6× lower on CUDA (#227).

### Fixed

- `nscbc_outlet` no longer diverges when eddies reverse the flow (#238).
