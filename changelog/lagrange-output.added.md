- Snapshots of TENO runs show the high-order solution: by default a whole-mesh `vtkhdf` or `vtu` `[[write_data]]` entry of a TENO run also writes `PREFIX_high_order...`, every cell a VTK Lagrange cell of the reconstruction polynomials' degree (order 3: quadratic, order 5: quartic), whose nodes hold `RHO`, `U`, `P`, `T`, `MACH` and the other state fields from the polynomials, so ParaView draws the field inside each cell rather than a constant; pyramids are written as two Lagrange tetrahedra and cells on curved boundaries with their exact shape; the solution files and restarts stay cell averages, unchanged byte for byte; `high_order = false` writes the cell values alone, and `mallard input upgrade` notes the new default for entries that do not set it. `mallard check` reports each entry's projected bytes per snapshot with and without the view and warns (`W-OUTPUT-SIZE`) above 10 GB, and `mallard post derive --high-order on` writes the view for runs written without it ([#1448](https://github.com/MatthewBonanni/mallard/issues/1448)).
