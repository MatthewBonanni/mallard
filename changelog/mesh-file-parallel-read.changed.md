- Gmsh files are read by every rank of a distributed run together, each parsing its share of the nodes and elements, so no rank holds the whole mesh, and the parser is about 15 times faster. On 8M hexahedra (a 1.2 GB Gmsh 2.2 file), reading takes 5.5 s instead of 101 s on one rank and 1.8 s instead of 107 s on 3 ranks, whose largest peak memory falls from 1,455 MB (rank 0) to 496 MB. Meshes are bitwise unchanged (#1045).
- **The Gmsh reader expects one entry per line, as Gmsh writes files:** a blank line or an entry split over lines inside `$Nodes` or `$Elements` is now an error, which names the line (`malformed or ends early (line N)`), and so are coordinates that are not finite (`nan`, `inf`). Export the file again from Gmsh if it was edited by hand (#1045).
