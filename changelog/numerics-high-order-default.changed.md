- **Changed behavior:** an input that sets neither `[numerics] preset` nor `[numerics.face_reconstruction]` now runs the `high_order` preset (TENO-E 5, HLLC, SSPRK3, and `cfl = 1.0` when `[run]` sets neither `cfl` nor `dt`) instead of first order. Keys the input sets still win, and the terminal output and the run block's `preset.default` say the default was used. To reproduce older first-order results, add `[numerics.face_reconstruction] type = "FO"`; `mallard input upgrade` prints a note for the inputs this concerns and leaves them unchanged. The presets are named by their order (`second_order`, `high_order`; see Deprecated), and the new `first_order` preset (FO, HLL, SSPRK3, `cfl = 0.5`) is for debugging, start-up transients and the last fallback. The numerics guide shows, measured, why high order is the default: on smooth flow it reaches a given error at a fraction of the cost.
