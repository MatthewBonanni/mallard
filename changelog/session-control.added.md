- `mallard ctl` reaches a run from anywhere, by its directory or its run ID: through its socket on rank 0's host, `srun --overlap` into its Slurm job, `kubectl exec` into its pod, `ssh` to a PBS or LSF node, or a signal (`kill`, `scancel`, `qsig`, `bkill`), as the run's new endpoint record `mallard.run.json` says. Control files only with `--allow-files`. See [Controlling a run from anywhere](docs/guide/running.md#controlling-a-run-from-anywhere).
- Control requests are acknowledged: the run answers `accepted` at once and `done` (with the restart file or the settings applied) once it has acted, and records every request, signals and control files included, as a `control` record of `mallard.jsonl`. `mallard ctl --wait accepted|done --timeout S --format json --id ID`.
- `mallard -i input.toml --detach` starts a run in the background and returns its run ID once it has started; the session's `run.launch` and `run.control` launch and control runs.
