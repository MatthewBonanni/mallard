- Boundary expressions read the boundary's local coordinates, which follow the shape of the entry's faces: `u` and `v` (3D) run from 0 to 1 across a four-sided patch, a ring (annulus, side of a pipe or cone) or a disk, `u` along a 2D boundary, and `n` from 0 on the walls to 1 at the point farthest from them, so a profile such as `"U * 16 * u * (1 - u) * v * (1 - v)"`, `"1 - r^2"` or `"n^(1/7)"` fits a duct or a pipe of any size and place with no dimensions or axes. Each has a twin in meters measured along the boundary (`u_m`, `v_m`, `n_m`: `"min(n_m / 0.01, 1)^(1/7)"`); on rings and disks `r`, `r_m` and `theta` name `v`, `v_m` and `2 * pi * u`. `corners` gives the corners of a four-sided patch and `walls` the zones `n` measures from; the run log shows each entry's patch and coordinate ranges. A local variable of the same name (`var u := y`) hides a coordinate, so existing expressions keep their meaning (`examples/channel_inlet`, [#704](https://github.com/MatthewBonanni/mallard/issues/704), [#1254](https://github.com/MatthewBonanni/mallard/issues/1254)).
